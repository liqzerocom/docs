Private WebSocket streams give your application per-account visibility into order status changes, trade fills, balance updates, and other account events in real time. Because these streams expose sensitive order data, you must authenticate the connection before subscribing to any private topic. LiqZero immediately terminates unauthenticated connections that attempt to subscribe to private topics.

**Private Mainnet endpoint:** `wss://ws.liqzero.com/ws/stream/{account_id}`  
**Private Testnet endpoint:** `wss://testnet-ws.liqzero.com/ws/stream/{account_id}`

Replace `{account_id}` with your registered LiqZero account ID.

## Authentication

After opening the WebSocket connection, send an `auth` event before any subscribe messages. The authentication payload requires your `perpo-key` (ed25519 public key), a base64url-encoded ed25519 signature of the current Unix timestamp in milliseconds, and the timestamp itself.

```json Authentication message
{
  "id": "auth_req",
  "event": "auth",
  "params": {
    "orderly_key": "your_perpo_key",
    "sign": "base64url_ed25519_signature",
    "timestamp": 1649920583000
  }
}
```

<Steps>
  <Step title="Connect to the private endpoint">
    Open a WebSocket connection to `wss://ws.liqzero.com/ws/stream/{account_id}` using your account ID in the path.
  </Step>
  <Step title="Capture the current timestamp">
    Record the current Unix time in milliseconds. Use this value as-is for both the `timestamp` field and the message you sign.
  </Step>
  <Step title="Sign the timestamp">
    Create an ed25519 signature over the string representation of the timestamp (e.g., `"1649920583000"`) using your `perpo-key` private key. Encode the resulting signature bytes as base64url (no padding).
  </Step>
  <Step title="Send the auth message">
    Dispatch the `auth` event JSON shown above. Wait for a successful acknowledgement before sending any `subscribe` messages.
  </Step>
</Steps>

### Authentication Acknowledgement

```json Successful auth response
{
  "id": "auth_req",
  "event": "auth",
  "success": true,
  "ts": 1649920583100
}
```

<Warning>
The `timestamp` in your auth message must be within 5 seconds of the LiqZero server time. If your system clock is significantly skewed, authentication will fail. Synchronise your clock with an NTP source before connecting.
</Warning>

## Execution Report Stream

The `executionreport` topic is the primary private stream for order management. It fires in real time for every order lifecycle event: order placement (status `NEW`), partial fills (`PARTIAL_FILLED`), complete fills (`FILLED`), and cancellations (`CANCELLED`). Subscribe to all symbols or filter to specific instruments using the `params.symbol` field.

**Topic:** `executionreport`  
**Push interval:** Real-time — one message per order state transition  
**Authentication required:** Yes

### Subscribe

<CodeGroup>

```json All symbols
{
  "id": "clientID3",
  "topic": "executionreport",
  "event": "subscribe"
}
```

```json Filtered by symbol
{
  "id": "clientID3",
  "topic": "executionreport",
  "event": "subscribe",
  "params": {
    "symbol": "PERP_BTC_USDC,PERP_ETH_USDC"
  }
}
```

</CodeGroup>

### Subscription Parameters

<ParamField body="id" type="string" required>
  A unique client-generated identifier echoed back in the acknowledgement.
</ParamField>

<ParamField body="event" type="string" required>
  Must be `subscribe` to start receiving events, or `unsubscribe` to stop.
</ParamField>

<ParamField body="topic" type="string" required>
  Must be `executionreport`.
</ParamField>

<ParamField body="params" type="object">
  Optional filter parameters. Omit entirely to receive execution reports for all symbols in your account.
</ParamField>

<ParamField body="params.symbol" type="string">
  Comma-separated list of symbols to filter by, for example `PERP_BTC_USDC,PERP_ETH_USDC`. Defaults to all symbols if not provided.
</ParamField>

### Acknowledgement Response

```json Subscription acknowledgement
{
  "id": "clientID3",
  "event": "subscribe",
  "success": true,
  "ts": 1609924478533
}
```

### Response Fields

<ResponseField name="topic" type="string">
  Always `executionreport` for this stream.
</ResponseField>

<ResponseField name="ts" type="integer">
  Server-side Unix timestamp in milliseconds when this event was generated.
</ResponseField>

<ResponseField name="data.msgType" type="string">
  Always `EXECUTION_REPORT` for order lifecycle events.
</ResponseField>

<ResponseField name="data.symbol" type="string">
  The trading symbol for this order, e.g. `PERP_ETH_USDC`.
</ResponseField>

<ResponseField name="data.clientOrderId" type="string">
  The client-specified order ID you provided when placing the order. Empty string if not set.
</ResponseField>

<ResponseField name="data.orderId" type="integer">
  The exchange-assigned unique order identifier.
</ResponseField>

<ResponseField name="data.type" type="string">
  Order type: `LIMIT` or `MARKET`.
</ResponseField>

<ResponseField name="data.side" type="string">
  Order direction: `BUY` or `SELL`.
</ResponseField>

<ResponseField name="data.price" type="number">
  The limit price specified when the order was placed. Zero for market orders.
</ResponseField>

<ResponseField name="data.quantity" type="number">
  The total order quantity as originally specified.
</ResponseField>

<ResponseField name="data.tradeId" type="integer">
  The ID of the individual trade that triggered this event. Zero for non-fill events (e.g., `NEW`, `CANCELLED`).
</ResponseField>

<ResponseField name="data.executedPrice" type="number">
  The price at which this specific fill was executed. Zero if no fill occurred in this event.
</ResponseField>

<ResponseField name="data.executedQuantity" type="number">
  The quantity filled in this specific execution event. Zero for non-fill events.
</ResponseField>

<ResponseField name="data.totalExecutedQuantity" type="number">
  The cumulative quantity filled across all fills for this order so far.
</ResponseField>

<ResponseField name="data.avgExecutedPrice" type="number">
  The volume-weighted average fill price across all fills for this order.
</ResponseField>

<ResponseField name="data.fee" type="number">
  Fee charged for this specific fill.
</ResponseField>

<ResponseField name="data.feeAsset" type="string">
  The asset in which the fee is denominated — always `USDC`.
</ResponseField>

<ResponseField name="data.totalFee" type="number">
  Cumulative fees charged across all fills for this order.
</ResponseField>

<ResponseField name="data.status" type="string">
  Current order status. One of:
  - `NEW` — order accepted and resting on the book
  - `PARTIAL_FILLED` — order partially filled, still open
  - `FILLED` — order fully filled and closed
  - `CANCELLED` — order cancelled, no further fills will occur
</ResponseField>

<ResponseField name="data.reason" type="string">
  Human-readable reason string, populated on cancellation events. Empty for other statuses.
</ResponseField>

<ResponseField name="data.visibleQuantity" type="number">
  The remaining open quantity visible on the order book.
</ResponseField>

<ResponseField name="data.timestamp" type="integer">
  Exchange-side Unix timestamp in milliseconds of the event that triggered this report.
</ResponseField>

<ResponseField name="data.marginMode" type="string">
  Margin mode for this order: `CROSS` or `ISOLATED`.
</ResponseField>

<ResponseField name="data.maker" type="boolean">
  `true` if this fill was as a maker (resting order); `false` if taker (aggressor order).
</ResponseField>

<ResponseField name="data.match_id" type="string">
  Unique identifier of the match event that caused this fill.
</ResponseField>

<ResponseField name="data.seq" type="integer">
  Monotonically increasing sequence number. Use this to detect and handle out-of-order message delivery.
</ResponseField>

### Unsubscribe

```json Unsubscribe from execution reports
{
  "id": "clientID3",
  "event": "unsubscribe",
  "topic": "executionreport"
}
```

## Other Available Private Topics

In addition to `executionreport`, the following private topics are available on the same authenticated connection:

<Accordion title="balance">
  Fires when your account balance changes — after a deposit, withdrawal, fill, or fee charge. Use this to keep a live balance display in sync without polling the REST API.
</Accordion>

<Accordion title="position">
  Fires when your open positions change — after a fill that opens, increases, reduces, or closes a position, and after funding rate settlement.
</Accordion>

<Accordion title="settle">
  Fires when a PnL settlement completes. The payload contains the settled amount and the resulting balance change.
</Accordion>

<Accordion title="wallet">
  Fires on deposit and withdrawal state transitions — useful for showing users the live status of their in-flight transactions.
</Accordion>

<Accordion title="notifications">
  Fires for system-level notifications, including margin calls, liquidation warnings, and broker-level messages.
</Accordion>

<Accordion title="liquidationsaccount">
  Fires when one of your positions enters or exits the liquidation process. Monitor this topic to implement real-time margin health warnings in your UI.
</Accordion>

<Tip>
Subscribe to all private topics you need over a single authenticated connection — there is no per-topic connection overhead. One `auth` message covers all subsequent subscriptions on that connection.
</Tip>
