LiqZero's public WebSocket streams give your front-end instant access to live market data without requiring user authentication. Connect to the public base endpoint and subscribe to any combination of `orderbook` and `trade` topics across all available symbols. Both streams are available on Mainnet and Testnet and operate independently — you can subscribe to multiple symbols simultaneously over a single connection.

**Public Mainnet endpoint:** `wss://ws.liqzero.com/ws/stream/public`  
**Public Testnet endpoint:** `wss://testnet-ws.liqzero.com/ws/stream/public`

## Orderbook Stream

The orderbook stream delivers full depth-100 snapshots for a symbol, pushed every second. Each message replaces the previous snapshot entirely — there are no incremental diff updates. Render the full `bids` and `asks` arrays directly as your current order book state.

**Topic format:** `{symbol}@orderbook`  
**Example topic:** `PERP_ETH_USDC@orderbook`  
**Push interval:** Every 1 second (full snapshot)

### Subscribe

Send the following message after connecting to start receiving orderbook updates:

```json Subscribe to orderbook
{
  "id": "clientID2",
  "topic": "PERP_ETH_USDC@orderbook",
  "event": "subscribe"
}
```

### Subscription Parameters

<ParamField body="id" type="string" required>
  A unique identifier generated by your client. LiqZero echoes this value in the acknowledgement response so you can match it to your request.
</ParamField>

<ParamField body="event" type="string" required>
  Must be `subscribe` to start receiving data, or `unsubscribe` to stop.
</ParamField>

<ParamField body="topic" type="string" required>
  The topic to subscribe to. Use the format `{symbol}@orderbook`, for example `PERP_ETH_USDC@orderbook`.
</ParamField>

### Acknowledgement Response

```json Subscription acknowledgement
{
  "id": "clientID2",
  "event": "subscribe",
  "success": true,
  "ts": 1609924478533
}
```

### Orderbook Message

Once subscribed, you receive a full orderbook snapshot once per second:

```json Orderbook snapshot
{
  "topic": "PERP_ETH_USDC@orderbook",
  "ts": 1614152140945,
  "data": {
    "symbol": "PERP_ETH_USDC",
    "asks": [
      [2000.50, 0.80],
      [2001.00, 3.00],
      [2001.25, 1.50]
    ],
    "bids": [
      [2000.00, 1.50],
      [1999.50, 2.00],
      [1999.00, 5.00]
    ]
  }
}
```

### Response Fields

<ResponseField name="topic" type="string">
  The topic that generated this message, in the format `{symbol}@orderbook`.
</ResponseField>

<ResponseField name="ts" type="integer">
  Server-side Unix timestamp in milliseconds when the snapshot was generated.
</ResponseField>

<ResponseField name="data.symbol" type="string">
  The trading symbol this snapshot belongs to, e.g. `PERP_ETH_USDC`.
</ResponseField>

<ResponseField name="data.asks" type="array">
  Array of ask price levels, each represented as `[price, quantity]`. Sorted ascending by price — the best (lowest) ask is first.
</ResponseField>

<ResponseField name="data.bids" type="array">
  Array of bid price levels, each represented as `[price, quantity]`. Sorted descending by price — the best (highest) bid is first.
</ResponseField>

<Note>
Each snapshot contains up to 100 price levels per side. A price level appearing in the snapshot with a quantity of `0` indicates that level has been cleared — treat it as absent from the book.
</Note>

### Unsubscribe

```json Unsubscribe from orderbook
{
  "id": "clientID2",
  "event": "unsubscribe",
  "topic": "PERP_ETH_USDC@orderbook"
}
```

## Trade Stream

The trade stream fires a real-time event every time a trade executes on LiqZero's shared orderbook for the subscribed symbol. Use this stream to build a live trade ticker, calculate rolling volume, or trigger UI animations when price changes.

**Topic format:** `{symbol}@trade`  
**Example topic:** `PERP_ETH_USDC@trade`  
**Push interval:** Real-time — one message per trade execution

### Subscribe

```json Subscribe to trade
{
  "id": "clientID3",
  "topic": "PERP_ETH_USDC@trade",
  "event": "subscribe"
}
```

### Subscription Parameters

<ParamField body="id" type="string" required>
  A unique identifier generated by your client. LiqZero echoes this value in the acknowledgement response.
</ParamField>

<ParamField body="event" type="string" required>
  Must be `subscribe` to start receiving data, or `unsubscribe` to stop.
</ParamField>

<ParamField body="topic" type="string" required>
  The topic to subscribe to. Use the format `{symbol}@trade`, for example `PERP_ETH_USDC@trade`.
</ParamField>

### Acknowledgement Response

```json Subscription acknowledgement
{
  "id": "clientID3",
  "event": "subscribe",
  "success": true,
  "ts": 1609924478533
}
```

### Trade Message

Each trade execution on the matched orderbook generates one message:

```json Trade execution event
{
  "topic": "PERP_ETH_USDC@trade",
  "ts": 1618820361552,
  "data": {
    "symbol": "PERP_ETH_USDC",
    "price": 2000.25,
    "size": 0.50,
    "side": "BUY"
  }
}
```

### Response Fields

<ResponseField name="topic" type="string">
  The topic that generated this message, in the format `{symbol}@trade`.
</ResponseField>

<ResponseField name="ts" type="integer">
  Server-side Unix timestamp in milliseconds when the trade was matched.
</ResponseField>

<ResponseField name="data.symbol" type="string">
  The trading symbol, e.g. `PERP_ETH_USDC`.
</ResponseField>

<ResponseField name="data.price" type="number">
  The price at which the trade was executed.
</ResponseField>

<ResponseField name="data.size" type="number">
  The quantity of the base asset traded.
</ResponseField>

<ResponseField name="data.side" type="string">
  The aggressor side of the trade: `BUY` if a buy order was the taker, `SELL` if a sell order was the taker.
</ResponseField>

<Tip>
To build a running trade history, append each trade event to a bounded array and pop the oldest entry when the array exceeds your desired length. The `side` field reflects the taker's direction, which is the standard convention for public trade feeds.
</Tip>

### Unsubscribe

```json Unsubscribe from trade
{
  "id": "clientID3",
  "event": "unsubscribe",
  "topic": "PERP_ETH_USDC@trade"
}
```

## Subscribing to Multiple Symbols

You can subscribe to both topics across multiple symbols over a single WebSocket connection. Send one subscribe message per topic — there is no batch subscribe API for public streams.

<CodeGroup>

```json ETH Orderbook
{
  "id": "sub_eth_ob",
  "topic": "PERP_ETH_USDC@orderbook",
  "event": "subscribe"
}
```

```json BTC Trade
{
  "id": "sub_btc_trade",
  "topic": "PERP_BTC_USDC@trade",
  "event": "subscribe"
}
```

```json SOL Orderbook
{
  "id": "sub_sol_ob",
  "topic": "PERP_SOL_USDC@orderbook",
  "event": "subscribe"
}
```

</CodeGroup>

<Warning>
Subscribing to a large number of high-frequency topics over a single connection may cause message queuing on your client. For production applications processing many symbols simultaneously, consider distributing subscriptions across multiple WebSocket connections.
</Warning>
