LiqZero exposes two complementary interfaces for integrating perpetual futures trading into your platform: a RESTful API for creating and managing orders, accounts, and assets, and a WebSocket API for real-time market data and execution feed subscriptions. Both interfaces share the same base domain and authentication model, so your integration code can reuse the same signing logic across all request types.

## Base Endpoints

Point all API calls at the environment that matches your deployment stage. Never mix mainnet credentials with testnet endpoints or vice versa.

| Environment | Base URL |
|---|---|
| **Mainnet** | `https://api.liqzero.com/` |
| **Testnet** | `https://testnet-api.liqzero.com` |

<Note>
  Always build and validate your integration against the Testnet environment before switching to Mainnet. Testnet funds carry no real value and orders do not affect live markets.
</Note>

## REST Request Conventions

Follow these conventions for every request to the LiqZero REST API:

- **GET** and **DELETE** requests: send all parameters as a **query string** in the URL.
- **POST** and **PUT** requests: send all parameters in the **request body** as JSON, with the `Content-Type: application/json` header.
- Parameters may be sent in any order within their respective location (query string or body).

<Tip>
  For `GET` and `DELETE` requests, set `Content-Type: application/x-www-form-urlencoded` — this is required for correct signature verification. See [Authentication](/api-reference/authentication) for the full signing procedure.
</Tip>

## Symbol Format

LiqZero identifies every perpetual market using the format `PERP_<TOKEN>_USDC`, where `<TOKEN>` is the uppercase base asset ticker. All symbols are quoted in USDC.

| Example Symbol | Market |
|---|---|
| `PERP_ETH_USDC` | ETH perpetual futures |
| `PERP_BTC_USDC` | BTC perpetual futures |
| `PERP_SOL_USDC` | SOL perpetual futures |
| `PERP_ARB_USDC` | ARB perpetual futures |

## Rate Limits

Rate limits are enforced per LiqZero key. When your application exceeds the rate limit for an endpoint, the server returns HTTP `429`. Back off and wait for the next rate-limit window before retrying. Retrying immediately will not succeed and may extend the backoff period.

<Warning>
  Sharing a single LiqZero key across multiple concurrent processes or users will pool their request counts against a single rate limit. Issue a separate key per integration context where high throughput is expected.
</Warning>

## Error Format

All API failures return a consistent JSON object containing three fields:

```json
{
  "success": false,
  "code": -1005,
  "message": "order_price must be a positive number"
}
```

| Field | Type | Description |
|---|---|---|
| `success` | boolean | Always `false` on error |
| `code` | integer | Numeric error code identifying the failure category |
| `message` | string | Human-readable description of the specific error |

Successful responses set `"success": true` and include a `data` object with the result payload alongside a `timestamp` field in Unix milliseconds.
