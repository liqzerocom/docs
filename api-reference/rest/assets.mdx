The Assets API covers all fund movement operations on the LiqZero platform. Deposits are initiated on-chain by interacting with the LiqZero vault smart contract — the API is not involved in the deposit flow. Withdrawals and PnL settlement are initiated through these endpoints. All private endpoints require [authentication](/api-reference/authentication).

<Note>
  Deposits are processed on-chain. After a user sends USDC to the vault contract, funds appear in their LiqZero account automatically once the transaction confirms. Use the [Asset History](#get-asset-history) endpoint to monitor deposit status.
</Note>

## Get Withdrawal Nonce

Retrieve a one-time nonce required to construct the withdrawal signature. Fetch a fresh nonce immediately before each withdrawal request, as nonces are single-use.

**`GET /v1/withdrawal_nonce`**

Requires authentication.

### Example Request

```bash cURL
curl --request GET \
  --url https://api.liqzero.com/v1/withdrawal_nonce \
  --header 'perpo-account-id: <your-account-id>' \
  --header 'perpo-key: <your-public-key>' \
  --header 'perpo-signature: <computed-signature>' \
  --header 'perpo-timestamp: 1649920583000'
```

### Response

```json
{
  "success": true,
  "data": {
    "withdrawal_nonce": 42
  },
  "timestamp": 1702989203989
}
```

<ResponseField name="withdrawal_nonce" type="number">
  An incrementing integer nonce. Include this value in the EIP-712 typed data signed by the user's wallet when submitting the withdrawal request.
</ResponseField>

## Create Withdraw Request

Submit a signed withdrawal request to move USDC from the user's LiqZero account to their on-chain wallet. The user must sign the withdrawal payload using their wallet (EIP-712) before this API call is made.

**`POST /v1/withdraw_request`**

Requires authentication.

### Request Parameters

<ParamField body="brokerId" type="string" required>
  Your builder ID.
</ParamField>

<ParamField body="chainId" type="integer" required>
  The chain ID identifying the destination network for the withdrawal (e.g. `42161` for Arbitrum One).
</ParamField>

<ParamField body="receiver" type="string" required>
  The on-chain wallet address that will receive the withdrawn USDC.
</ParamField>

<ParamField body="token" type="string" required>
  The token to withdraw. Currently only `"USDC"` is supported.
</ParamField>

<ParamField body="amount" type="number" required>
  The amount of USDC to withdraw, expressed in human-readable units (not wei).
</ParamField>

<ParamField body="withdrawNonce" type="number" required>
  The nonce obtained from `GET /v1/withdrawal_nonce`. Prevents replay attacks.
</ParamField>

<ParamField body="timestamp" type="integer" required>
  Unix timestamp in milliseconds at the time of signing. Must match the timestamp in the EIP-712 payload.
</ParamField>

<ParamField body="signature" type="string" required>
  EIP-712 wallet signature produced by the user authorizing this specific withdrawal amount and receiver.
</ParamField>

### Example Request

```bash cURL
curl --request POST \
  --url https://api.liqzero.com/v1/withdraw_request \
  --header 'Content-Type: application/json' \
  --header 'perpo-account-id: <your-account-id>' \
  --header 'perpo-key: <your-public-key>' \
  --header 'perpo-signature: <computed-signature>' \
  --header 'perpo-timestamp: 1649920583000' \
  --data '{
    "brokerId": "my_builder_id",
    "chainId": 42161,
    "receiver": "0xUserWalletAddress",
    "token": "USDC",
    "amount": 500.00,
    "withdrawNonce": 42,
    "timestamp": 1649920583000,
    "signature": "0xWalletSignatureHex..."
  }'
```

### Response

```json
{
  "success": true,
  "data": {
    "withdrawal_id": "wd_8f3a2b1c9d4e",
    "status": "PROCESSING"
  },
  "timestamp": 1702989203989
}
```

<ResponseField name="withdrawal_id" type="string">
  Unique identifier for this withdrawal request. Use this to monitor withdrawal status via the [Asset History](#get-asset-history) endpoint.
</ResponseField>

<ResponseField name="status" type="string">
  Initial status of the withdrawal. Returns `"PROCESSING"` when the request is accepted and queued for on-chain settlement.
</ResponseField>

<Warning>
  If the account has outstanding arrears (negative USDC balance from unsettled losses), the withdrawal will be rejected with error `-1009`. Deposit sufficient USDC to clear the deficit before attempting to withdraw.
</Warning>

## Get Asset History

Retrieve a paginated history of deposit and withdrawal transactions for the authenticated account. Use this to display fund movement history in your UI and to monitor the status of pending withdrawals.

**`GET /v1/asset/history`**

Requires authentication.

### Query Parameters

<ParamField query="token" type="string">
  Filter by token symbol. Defaults to all tokens. Currently `"USDC"` is the primary supported token.
</ParamField>

<ParamField query="type" type="string">
  Filter by transaction type. Accepted values: `DEPOSIT` or `WITHDRAW`.
</ParamField>

<ParamField query="page" type="number">
  Page number to retrieve, starting at `1`. Defaults to `1`.
</ParamField>

<ParamField query="limit" type="number">
  Number of records per page. Maximum is `100`. Defaults to `25`.
</ParamField>

### Example Request

```bash cURL
curl --request GET \
  --url 'https://api.liqzero.com/v1/asset/history?type=WITHDRAW&page=1&limit=25' \
  --header 'perpo-account-id: <your-account-id>' \
  --header 'perpo-key: <your-public-key>' \
  --header 'perpo-signature: <computed-signature>' \
  --header 'perpo-timestamp: 1649920583000'
```

### Response

```json
{
  "success": true,
  "data": {
    "meta": {
      "total": 5,
      "records_per_page": 25,
      "current_page": 1
    },
    "rows": [
      {
        "id": "wd_8f3a2b1c9d4e",
        "tx_id": "0xOnChainTxHash...",
        "type": "WITHDRAW",
        "token": "USDC",
        "amount": 500.00,
        "status": "COMPLETED",
        "created_time": 1653563963000,
        "updated_time": 1653564213000
      }
    ]
  },
  "timestamp": 1702989203989
}
```

<ResponseField name="rows[].id" type="string">
  Unique transaction record ID (matches the `withdrawal_id` from the withdraw request endpoint).
</ResponseField>

<ResponseField name="rows[].tx_id" type="string">
  On-chain transaction hash once the transaction has been broadcast. May be `null` while the status is `PROCESSING`.
</ResponseField>

<ResponseField name="rows[].type" type="string">
  Transaction type: `DEPOSIT` or `WITHDRAW`.
</ResponseField>

<ResponseField name="rows[].token" type="string">
  Token symbol, e.g. `USDC`.
</ResponseField>

<ResponseField name="rows[].amount" type="number">
  Transaction amount in human-readable USDC units.
</ResponseField>

<ResponseField name="rows[].status" type="string">
  Current transaction status. Possible values:
  - `PROCESSING` — request accepted, awaiting on-chain execution
  - `COMPLETED` — transaction confirmed on-chain
  - `FAILED` — transaction failed; no funds were moved
</ResponseField>

<ResponseField name="rows[].created_time" type="integer">
  Record creation time as a 13-digit Unix timestamp in milliseconds.
</ResponseField>

<ResponseField name="rows[].updated_time" type="integer">
  Last status update time as a 13-digit Unix timestamp in milliseconds.
</ResponseField>

## Settle PnL

Settle the account's accumulated realized PnL into the USDC balance. Call this endpoint to crystallize unrealized funding credits or realized trading profits so they become available as free collateral for withdrawal or further trading.

**`POST /v1/settle_pnl`**

Requires authentication. No request body is required.

### Example Request

```bash cURL
curl --request POST \
  --url https://api.liqzero.com/v1/settle_pnl \
  --header 'Content-Type: application/json' \
  --header 'perpo-account-id: <your-account-id>' \
  --header 'perpo-key: <your-public-key>' \
  --header 'perpo-signature: <computed-signature>' \
  --header 'perpo-timestamp: 1649920583000'
```

### Response

```json
{
  "success": true,
  "data": {
    "settle_id": "settle_3c1a8d2f"
  },
  "timestamp": 1702989203989
}
```

<ResponseField name="settle_id" type="string">
  Unique identifier for this settlement request. The settlement is processed asynchronously — the USDC balance update will reflect within a few seconds.
</ResponseField>

<Tip>
  Prompt your users to settle PnL before requesting a withdrawal if their free collateral is lower than expected. Unsettled PnL is not included in the withdrawable balance until settlement completes.
</Tip>
