Every private LiqZero API endpoint requires cryptographic request signing using the [ed25519 elliptic curve standard](https://ed25519.cr.yp.to/). Rather than passing an API key and secret in a traditional header pair, you sign a normalized representation of each request with your ed25519 private key and send the resulting signature alongside your public key and account ID. This design means your private key never leaves your environment — the server only needs your public key to verify the signature.

## Required Headers

Include the following headers on every authenticated request:

| Header | Description |
|---|---|
| `Content-Type` | `application/json` for POST/PUT; `application/x-www-form-urlencoded` for GET/DELETE |
| `perpo-account-id` | Your LiqZero account ID, obtained during registration |
| `perpo-key` | Your ed25519 public key **without** the `ed25519:` prefix |
| `perpo-signature` | ed25519 signature of the normalized request, base64url-encoded |
| `perpo-timestamp` | Current Unix timestamp in milliseconds |

<Note>
  When referencing your key in code samples, strip the `ed25519:` prefix from the stored value before assigning it to the `perpo-key` header.
</Note>

## Signing Steps

<Steps>
  <Step title="Obtain your account ID">
    Register your account to receive a unique account ID. Pass this value as the `perpo-account-id` header on every authenticated request. See the [Accounts API](/api-reference/rest/accounts) for the registration flow.
  </Step>

  <Step title="Set your perpo-key">
    Generate an ed25519 key pair and register the public key with LiqZero. Add the public key (without the `ed25519:` prefix) to the `perpo-key` header. See the [Accounts API](/api-reference/rest/accounts) for how to register a new key.
  </Step>

  <Step title="Capture the current timestamp">
    Record the current Unix time in **milliseconds** and add it to the `perpo-timestamp` header. This value must also appear at the start of the normalized message you sign in the next step.
  </Step>

  <Step title="Normalize the request content">
    Build the message string by concatenating the following parts **with no separator**:

    1. The timestamp in milliseconds (e.g. `1649920583000`)
    2. The HTTP method in uppercase (e.g. `POST`)
    3. The request path **including** any query string, but without the base URL (e.g. `/v1/orders?symbol=PERP_BTC_USDC`)
    4. (Optional) If the request has a JSON body, append the JSON-stringified body

    **Example normalized message for a limit order:**
    ```
    1649920583000POST/v1/order{"symbol": "PERP_ETH_USDC", "order_type": "LIMIT", "order_price": 1521.03, "order_quantity": 2.11, "side": "BUY"}
    ```

    **Example normalized message for a GET request with query parameters:**
    ```
    1649920583000GET/v1/orders?symbol=PERP_ETH_USDC&status=NEW
    ```
  </Step>

  <Step title="Sign and encode the message">
    Sign the UTF-8 encoded normalized string using the ed25519 algorithm with your private key. Encode the resulting 64-byte signature using **base64 URL-safe encoding** (no padding required). Set the result as the `perpo-signature` header value.
  </Step>

  <Step title="Set the Content-Type header">
    - For `GET` and `DELETE` requests: `Content-Type: application/x-www-form-urlencoded`
    - For `POST` and `PUT` requests: `Content-Type: application/json`
  </Step>

  <Step title="Send the request with all headers">
    Your final request must include all five authentication headers. The server validates the timestamp, verifies the signature against the normalized content, and checks that the key is registered and active before processing the request.
  </Step>
</Steps>

## Code Examples

The examples below demonstrate the complete signing flow, including loading your private key, building the normalized message, and dispatching the signed request.

<CodeGroup>

```typescript signer.ts
import { getPublicKeyAsync, signAsync } from '@noble/ed25519';
import { encodeBase58 } from 'ethers';

export async function signAndSendRequest(
  liqzeroAccountId: string,
  privateKey: Uint8Array | string,
  input: URL | string,
  init?: RequestInit | undefined
): Promise<Response> {
  const timestamp = Date.now();
  const encoder = new TextEncoder();

  const url = new URL(input);
  let message = `${String(timestamp)}${init?.method ?? 'GET'}${url.pathname}${url.search}`;
  if (init?.body) {
    message += init.body;
  }
  const liqzeroSignature = await signAsync(encoder.encode(message), privateKey);

  return fetch(input, {
    headers: {
      'Content-Type':
        init?.method !== 'GET' && init?.method !== 'DELETE'
          ? 'application/json'
          : 'application/x-www-form-urlencoded',
      'perpo-timestamp': String(timestamp),
      'perpo-account-id': liqzeroAccountId,
      'perpo-key': encodeBase58(await getPublicKeyAsync(privateKey)),
      'perpo-signature': Buffer.from(liqzeroSignature).toString('base64url'),
      ...(init?.headers ?? {})
    },
    ...(init ?? {})
  });
}
```

```python signer.py
from base58 import b58encode
from base64 import urlsafe_b64encode
from datetime import datetime
import json
import math
from cryptography.hazmat.primitives.asymmetric.ed25519 import Ed25519PrivateKey
from requests import PreparedRequest, Request
import urllib

class Signer(object):
    def __init__(self, account_id: str, private_key: Ed25519PrivateKey) -> None:
        self._account_id = account_id
        self._private_key = private_key

    def sign_request(self, req: Request) -> PreparedRequest:
        d = datetime.utcnow()
        epoch = datetime(1970, 1, 1)
        timestamp = math.trunc((d - epoch).total_seconds() * 1_000)

        url = urllib.parse.urlparse(req.url)
        message = str(timestamp) + req.method + url.path
        if len(url.query) > 0:
            message += "?" + url.query
        if req.json is not None:
            message += json.dumps(req.json)

        liqzero_signature = urlsafe_b64encode(
            self._private_key.sign(message.encode())
        ).decode("utf-8")

        req.headers = {
            "perpo-timestamp": str(timestamp),
            "perpo-account-id": self._account_id,
            "perpo-key": b58encode(
                self._private_key.public_key().public_bytes_raw()
            ).decode("utf-8"),
            "perpo-signature": liqzero_signature,
        }
        if req.method == "GET" or req.method == "DELETE":
            req.headers["Content-Type"] = "application/x-www-form-urlencoded"
        elif req.method == "POST" or req.method == "PUT":
            req.headers["Content-Type"] = "application/json"

        return req.prepare()
```

```python authentication_example.py
import json
import os
from base58 import b58decode
from requests import Request, Session
from cryptography.hazmat.primitives.asymmetric.ed25519 import Ed25519PrivateKey
from signer import Signer

base_url = "https://api.liqzero.com"
liqzero_account_id = "<your-account-id>"

key = b58decode(os.environ.get("LIQZERO_SECRET"))
liqzero_key = Ed25519PrivateKey.from_private_bytes(key)

session = Session()
signer = Signer(liqzero_account_id, liqzero_key)

req = signer.sign_request(
    Request(
        "POST",
        "%s/v1/order" % base_url,
        json={
            "symbol": "PERP_ETH_USDC",
            "order_type": "MARKET",
            "order_quantity": 0.01,
            "side": "BUY",
        },
    )
)
res = session.send(req)
response = json.loads(res.text)
print(response)
```

import net.i2p.crypto.eddsa.EdDSAPrivateKey;
import net.i2p.crypto.eddsa.spec.EdDSANamedCurveTable;
import net.i2p.crypto.eddsa.spec.EdDSAParameterSpec;
import net.i2p.crypto.eddsa.spec.EdDSAPrivateKeySpec;
import okhttp3.OkHttpClient;
import okhttp3.Request;
import okhttp3.Response;
import org.bitcoinj.base.Base58;
import org.json.JSONObject;

public class AuthenticationExample {
    public static void main(String[] args) throws Exception {
        String baseUrl = "https://api.liqzero.com";
        String liqzeroAccountId = "<your-account-id>";

        Dotenv dotenv = Dotenv.load();
        OkHttpClient client = new OkHttpClient();

        String key = dotenv.get("LIQZERO_SECRET");
        EdDSAParameterSpec spec = EdDSANamedCurveTable.getByName(EdDSANamedCurveTable.ED_25519);
        EdDSAPrivateKeySpec encoded = new EdDSAPrivateKeySpec(Base58.decode(key), spec);
        EdDSAPrivateKey liqzeroKey = new EdDSAPrivateKey(encoded);

        Signer signer = new Signer(baseUrl, liqzeroAccountId, liqzeroKey);

        json.put("side", "BUY");

        Request req = signer.createSignedRequest("/v1/order", "POST", json);
        String res;
        try (Response response = client.newCall(req).execute()) {
            res = response.body().string();
        }
        JSONObject obj = new JSONObject(res);
        System.out.println(obj.toString(2));
    }
}

## Security Validation

LiqZero validates every incoming request through three independent checks. A request must pass all three to be accepted.

<Accordion title="Request Timestamp Check">
  The `perpo-timestamp` header value must be within **300 seconds** of the API server's current time. Requests with timestamps older or newer than this window are rejected with error `-1002`. Keep your system clock synchronized with NTP to avoid intermittent failures.
</Accordion>

<Accordion title="Signature Verification">
  The `perpo-signature` header must be a valid ed25519 signature produced by signing the normalized request string (timestamp + method + path+query + optional body) with the private key that corresponds to the public key in `perpo-key`. Any mismatch — including differences in JSON field ordering or whitespace in the body — will produce an invalid signature.
</Accordion>

<Accordion title="Key Validity Check">
  The `perpo-key` header must reference a key that satisfies all of the following:
  - **Registered** — the key has been added to LiqZero via the [Accounts API](/api-reference/rest/accounts)
  - **Associated** — the key is linked to the account identified by `perpo-account-id`
  - **Not expired** — the key has not passed its expiry date or been revoked
</Accordion>

## Common Authentication Errors

| Error Code | Cause | Resolution |
|---|---|---|
| `-1001` | The `perpo-key` header is malformed or uses an unsupported format | Ensure the key is a valid base58-encoded ed25519 public key without the `ed25519:` prefix |
| `-1002` | The key is invalid, has insufficient permissions, or has expired | Re-register the key via the [Accounts API](/api-reference/rest/accounts), check account association, and verify the key has not expired |

See the full [Error Codes](/api-reference/error-codes) reference for all possible failure codes.
