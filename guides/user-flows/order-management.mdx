Every trade on LiqZero passes through a layered processing pipeline: your application submits an order via the REST API, the messaging layer authenticates it using your Trading Key, the matching engine pairs it against the shared orderbook, and the settlement layer records the final execution on-chain. Understanding this flow lets you build reliable order management UIs and handle every state transition gracefully.

## Order Lifecycle

When your application places an order, it moves through LiqZero's architecture in five distinct stages:

1. Your **builder front-end** forwards the request with the user's Trading Key in the authentication headers
2. The **messaging layer** verifies the ed25519 signature on the Trading Key
3. The **engine layer** matches the order against the shared orderbook
4. On execution, trade data is uploaded to the **settlement layer**
5. The user receives order and execution updates — both in the REST response and via WebSocket push

The status of an order transitions through the following states:

| Status | Meaning |
|---|---|
| `NEW` | Order accepted by the engine, awaiting a match |
| `PARTIAL_FILLED` | A portion of the order has been executed |
| `FILLED` | The entire order quantity has been executed |
| `CANCELLED` | The order was cancelled before full execution |
| `REJECTED` | The order was rejected at submission (e.g., insufficient margin) |

## Order Types

LiqZero supports the following order types. Specify `order_type` in your request body:

| Type | Behavior |
|---|---|
| `LIMIT` | Rests on the book at the specified price; executes at `order_price` or better |
| `MARKET` | Executes immediately at the best available price; no `order_price` required |
| `IOC` | Immediate-or-Cancel — fills as much as possible instantly, cancels the remainder |
| `FOK` | Fill-or-Kill — must fill the entire quantity immediately or the order is cancelled |
| `POST_ONLY` | Enters the book as a maker only; rejected if it would match immediately |

## Symbol Format

All LiqZero markets follow the `PERP_<TOKEN>_USDC` convention. For example:
- `PERP_ETH_USDC` — ETH perpetual quoted in USDC
- `PERP_BTC_USDC` — BTC perpetual quoted in USDC
- `PERP_SOL_USDC` — SOL perpetual quoted in USDC

## API Reference

### Create Order

Place a new order for a user account.

**`POST /v1/order`**

<Tabs>
  <Tab title="Request Fields">
    <ParamField body="symbol" type="string" required>
      Market symbol in `PERP_<TOKEN>_USDC` format (e.g., `PERP_ETH_USDC`)
    </ParamField>
    <ParamField body="order_type" type="string" required>
      One of: `LIMIT`, `MARKET`, `IOC`, `FOK`, `POST_ONLY`
    </ParamField>
    <ParamField body="side" type="string" required>
      `BUY` or `SELL`
    </ParamField>
    <ParamField body="order_price" type="number">
      Limit price per unit. Required for `LIMIT`, `IOC`, `FOK`, and `POST_ONLY` orders.
    </ParamField>
    <ParamField body="order_quantity" type="number" required>
      Quantity of the base asset to trade
    </ParamField>
    <ParamField body="client_order_id" type="string">
      Optional idempotency key assigned by your application (max 36 chars)
    </ParamField>
    <ParamField body="margin_mode" type="string">
      `CROSS` or `ISOLATED`. Defaults to the symbol's configured margin mode.
    </ParamField>
    <ParamField body="reduce_only" type="boolean">
      When `true`, the order can only reduce an existing position, never increase it
    </ParamField>
  </Tab>
  <Tab title="Response Fields">
    <ResponseField name="success" type="boolean">
      `true` when the order was accepted by the engine
    </ResponseField>
    <ResponseField name="data.order_id" type="number">
      Unique order ID assigned by LiqZero. Use this for cancel and status queries.
    </ResponseField>
    <ResponseField name="data.client_order_id" type="string">
      Your application-assigned idempotency key, echoed back
    </ResponseField>
    <ResponseField name="data.order_type" type="string">
      Confirmed order type
    </ResponseField>
    <ResponseField name="data.order_price" type="number">
      Price at which the order was placed
    </ResponseField>
    <ResponseField name="data.order_quantity" type="number">
      Total quantity submitted
    </ResponseField>
    <ResponseField name="data.status" type="string">
      Initial status — typically `NEW`
    </ResponseField>
    <ResponseField name="data.timestamp" type="number">
      Order creation timestamp in UNIX milliseconds
    </ResponseField>
  </Tab>
</Tabs>

#### TypeScript Example — BUY LIMIT Order

<CodeGroup>
```typescript TypeScript
import crypto from "crypto";

const BASE_URL = "https://api.liqzero.com";
const ACCOUNT_ID = "0xYOUR_ACCOUNT_ID";
const TRADING_KEY_PUBLIC = "ed25519:YOUR_PUBLIC_KEY";
const TRADING_KEY_SECRET_HEX = "YOUR_SECRET_KEY_HEX"; // raw hex bytes of the ed25519 private key

function signRequest(
  method: string,
  path: string,
  body: string,
  timestamp: string
): string {
  const message = `${timestamp}${method.toUpperCase()}${path}${body}`;
  const privateKey = Buffer.from(TRADING_KEY_SECRET_HEX, "hex");
  const keyObject = crypto.createPrivateKey({
    key: privateKey,
    format: "der",
    type: "pkcs8",
  });
  const signature = crypto.sign(null, Buffer.from(message), keyObject);
  return signature.toString("base64url");
}

async function createLimitOrder() {
  const path = "/v1/order";
  const timestamp = Date.now().toString();

  const body = JSON.stringify({
    symbol: "PERP_ETH_USDC",
    order_type: "LIMIT",
    side: "BUY",
    order_price: 3200.00,
    order_quantity: 0.5,
    client_order_id: "my-order-001",
  });

  const signature = signRequest("POST", path, body, timestamp);

  const response = await fetch(`${BASE_URL}${path}`, {
    method: "POST",
    headers: {
      "Content-Type": "application/json",
      "perpo-account-id": ACCOUNT_ID,
      "perpo-key": TRADING_KEY_PUBLIC,
      "perpo-signature": signature,
      "perpo-timestamp": timestamp,
    },
    body,
  });

  const result = await response.json();
  console.log("Order placed:", result);
  return result;
}

createLimitOrder();
```

```json Request Body
}
```

### Cancel Order

Cancel a single open order by its order ID.

**`DELETE /v1/order`**

<ParamField query="order_id" type="number" required>
  The `order_id` returned when the order was created
</ParamField>
<ParamField query="symbol" type="string" required>
  The market symbol for the order (e.g., `PERP_ETH_USDC`)
</ParamField>

```json Response
{
  "success": true,
  "timestamp": 1712000050000,
  "data": {
    "order_id": 892734651,
    "status": "CANCELLED"
  }
}
```

<Warning>
  Cancelling an order that is already `FILLED` or `CANCELLED` returns error code `-1006`. Always check the current order status before attempting a cancel.
</Warning>

### Cancel All Orders

Cancel all open orders, optionally scoped to a single symbol.

**`DELETE /v1/orders`**

<ParamField query="symbol" type="string">
  Optional. Limit cancellations to a specific market symbol. Omit to cancel all open orders across all symbols.
</ParamField>

### Batch Create Orders

Submit up to 10 orders in a single request to reduce round-trip latency.

**`POST /v1/batch-order`**

The request body accepts an `orders` array, where each element uses the same fields as a single `POST /v1/order` request.

### Get Orders (List)

Retrieve a paginated list of orders filtered by status, symbol, or time range.

**`GET /v1/orders`**

<ParamField query="symbol" type="string">
  Filter by market symbol
</ParamField>
<ParamField query="status" type="string">
  Filter by order status: `NEW`, `PARTIAL_FILLED`, `FILLED`, `CANCELLED`
</ParamField>
<ParamField query="page" type="number">
  Page number (default: `1`)
</ParamField>
<ParamField query="size" type="number">
  Results per page (default: `25`, max: `500`)
</ParamField>

## Real-Time Updates via WebSocket

For low-latency order state changes, subscribe to the `executionreport` topic on the private WebSocket stream instead of polling REST. Every state transition — from `NEW` through `FILLED` — is pushed to your subscriber in real time.

```json Subscribe
{
  "id": "exec-sub-1",
  "topic": "executionreport",
  "event": "subscribe",
  "params": {
    "symbol": "PERP_ETH_USDC,PERP_BTC_USDC"
  }
}
```

```json Push Message
{
  "topic": "executionreport",
  "ts": 1712000123456,
  "data": {
    "symbol": "PERP_ETH_USDC",
    "orderId": 892734651,
    "clientOrderId": "my-order-001",
    "type": "LIMIT",
    "side": "BUY",
    "quantity": 0.5,
    "price": 3200.00,
    "executedQuantity": 0.5,
    "totalExecutedQuantity": 0.5,
    "avgExecutedPrice": 3199.50,
    "fee": 0.48,
    "feeAsset": "USDC",
    "status": "FILLED",
    "marginMode": "CROSS",
    "maker": true,
    "timestamp": 1712000123400
  }
}
```

<Tip>
  Omit `params.symbol` in your subscription message to receive execution reports for all symbols simultaneously. This is the recommended approach for platforms that display a global order history feed.
</Tip>

See the [WebSocket Execution Report](/api-reference/websocket/private-streams) reference for the full field listing and subscription options.
