Every perpetual futures position on LiqZero accumulates PnL — both realized (from closed trades) and unrealized (from open positions). This PnL does not automatically become part of your spendable USDC balance. To convert it, you must trigger a **PnL settlement** request. Settlement can be requested by the account owner at any time and is also triggerable by third parties (such as other traders or the platform itself) to keep system balances healthy.

You need to settle PnL before withdrawing profits, when you want to realize gains from a closed position, or as a routine risk management step to keep collateral balances accurate. The settlement flow requires a wallet EIP-712 signature — the same pattern used for deposits and withdrawals — to authorize the operation on-chain.

## When to Settle

- **Before withdrawal**: unsettled PnL cannot be withdrawn; it must be converted to USDC balance first
- **After closing a profitable position**: settlement crystallizes the gains into your available USDC
- **Risk management**: regular settlement keeps your collateral accounting clean and avoids accumulating large unsettled amounts

<Note>
  PnL settlement requests are processed asynchronously. After submitting, verify the settlement landed by polling `GET /v1/asset/history` and looking for a record with type `PNL_SETTLEMENT`.
</Note>

## Settlement Flow

<Steps>
  <Step title="Check Current PnL State">
    Before settling, inspect the account's current unsettled PnL so your UI can present accurate figures to the user.

    **`GET /v1/client/info`**

    ```json Response (relevant fields)
    {
      "success": true,
      "data": {
        "account_id": "0xYOUR_ACCOUNT_ID",
        "total_collateral_value": 5420.00,
        "free_collateral": 3100.00,
        "unsettled_pnl": 320.50,
        "realized_pnl": 140.00
      }
    }
    ```

    You can also retrieve per-position unsettled PnL via `GET /v1/positions` — the `unsettled_pnl` field on each position record shows the amount that will be transferred to USDC balance on settlement.
  </Step>

  <Step title="Obtain a Settlement Nonce">
    Every settlement request requires a fresh nonce to prevent replay attacks. Fetch one from the nonce endpoint. This call requires standard LiqZero authentication headers.

    **`GET /v1/settle_nonce`**

    ```json Response
    {
      "success": true,
      "timestamp": 1712002000000,
      "data": {
        "settle_nonce": 7
      }
    }
    ```

    <Warning>
      Nonces are single-use. Never reuse a `settle_nonce` across multiple settlement requests. A reused nonce will result in a rejected signature.
    </Warning>
  </Step>

  <Step title="Sign the EIP-712 Settlement Message">
    Construct and sign an EIP-712 typed message using the nonce from Step 2. Use the **on-chain domain** with the LiqZero Ledger contract address for the connected chain (find addresses at [Contract Addresses](/api-reference/contracts/addresses)).

    The message type is `SettlePnl`:

    ```json EIP-712 Message Structure
    {
      "brokerId": "your-builder-id",
      "chainId": 42161,
      "settleNonce": 7,
      "timestamp": 1712002000000
    }
    ```

    | Field | Type | Required | Description |
    |---|---|---|---|
    | `brokerId` | string | Yes | Your registered Builder ID on LiqZero |
    | `chainId` | int | Yes | Chain ID of the network where the message is signed |
    | `settleNonce` | int | Yes | The nonce obtained in Step 2 |
    | `timestamp` | timestamp | Yes | Current time in UNIX milliseconds |

    <CodeGroup>
    ```typescript TypeScript
    import { ethers } from "ethers";

    const CHAIN_ID = 42161; // Arbitrum One (mainnet)
    const LEDGER_CONTRACT = "0x6F7a338F2aA472838dEFD3283eB360d4Dff5D203";
    const BUILDER_ID = "your-builder-id";

    async function signSettlePnl(
      settleNonce: number,
      walletPrivateKey: string
    ): Promise<string> {
      const domain = {
        name: "LiqZero",
        version: "1",
        chainId: CHAIN_ID,
        verifyingContract: LEDGER_CONTRACT,
      };

      const types = {
        SettlePnl: [
          { name: "brokerId", type: "string" },
          { name: "chainId", type: "uint256" },
          { name: "settleNonce", type: "uint64" },
          { name: "timestamp", type: "uint64" },
        ],
      };

      const message = {
        brokerId: BUILDER_ID,
        chainId: CHAIN_ID,
        settleNonce: settleNonce,
        timestamp: Date.now(),
      };

      const wallet = new ethers.Wallet(walletPrivateKey);
      const signature = await wallet.signTypedData(domain, types, message);
      return signature;
    }
    ```

    ```python Python
    from eth_account import Account
    from eth_account.messages import encode_typed_data
    import time

    CHAIN_ID = 42161  # Arbitrum One (mainnet)
    LEDGER_CONTRACT = "0x6F7a338F2aA472838dEFD3283eB360d4Dff5D203"
    BUILDER_ID = "your-builder-id"

    def sign_settle_pnl(settle_nonce: int, private_key: str) -> str:
        data = {
            "types": {
                "EIP712Domain": [
                    {"name": "name", "type": "string"},
                    {"name": "version", "type": "string"},
                    {"name": "chainId", "type": "uint256"},
                    {"name": "verifyingContract", "type": "address"},
                ],
                "SettlePnl": [
                    {"name": "brokerId", "type": "string"},
                    {"name": "chainId", "type": "uint256"},
                    {"name": "settleNonce", "type": "uint64"},
                    {"name": "timestamp", "type": "uint64"},
                ],
            },
            "domain": {
                "name": "LiqZero",
                "version": "1",
                "chainId": CHAIN_ID,
                "verifyingContract": LEDGER_CONTRACT,
            },
            "primaryType": "SettlePnl",
            "message": {
                "brokerId": BUILDER_ID,
                "chainId": CHAIN_ID,
                "settleNonce": settle_nonce,
                "timestamp": int(time.time() * 1000),
            },
        }

        account = Account.from_key(private_key)
        signable_message = encode_typed_data(full_message=data)
        signed = account.sign_message(signable_message)
        return signed.signature.hex()
    ```
    </CodeGroup>
  </Step>

  <Step title="Submit the Settlement Request">
    Post the signed message to the settlement endpoint. Include both the standard LiqZero authentication headers and the EIP-712 signature payload.

    **`POST /v1/settle_pnl`**

    ```json Request Body
    {
      "signature": "0xabc123...your-eip712-signature",
      "userAddress": "0xYOUR_WALLET_ADDRESS",
      "verifyingContract": "0x6F7a338F2aA472838dEFD3283eB360d4Dff5D203",
      "message": {
        "brokerId": "your-builder-id",
        "chainId": "42161",
        "settleNonce": "7",
        "timestamp": "1712002000000"
      }
    }
    ```

    ```json Response
    {
      "success": true,
      "timestamp": 1712002100000,
      "data": {
        "settle_id": "settle-00192837"
      }
    }
    ```

    A `success: true` response confirms the request was accepted. Settlement is **processed asynchronously** — the USDC balance update is not immediate.
  </Step>

  <Step title="Verify Settlement via Asset History">
    Poll the asset history endpoint to confirm the settlement has been applied to the account balance.

    **`GET /v1/asset/history?type=PNL_SETTLEMENT`**

    ```json Response
    {
      "success": true,
      "data": {
        "rows": [
          {
            "id": "settle-00192837",
            "type": "PNL_SETTLEMENT",
            "amount": 320.50,
            "token": "USDC",
            "status": "COMPLETED",
            "created_time": 1712002100000,
            "updated_time": 1712002115000
          }
        ]
      }
    }
    ```

    When `status` is `COMPLETED`, the settled amount has been added to the account's USDC balance and is available for trading or withdrawal.
  </Step>
</Steps>

## Settlement Error Codes

If your settlement request is rejected, the API returns one of the following error codes:

| Code | HTTP Status | Meaning | Resolution |
|---|---|---|---|
| `-1008` | 400 | Settlement quantity exceeds the maximum allowed amount | Reduce the amount you are attempting to settle, or split into smaller requests |
| `-1009` | 400 | Cannot settle — account has outstanding deposit arrears | Deposit additional USDC to clear the arrears before requesting settlement |
| `-1003` | 429 | Rate limit exceeded on settlement requests | Wait before retrying; implement exponential back-off |
| `-1007` | 409 | Duplicate request — a settlement with this nonce already exists | Fetch a new nonce and resubmit |

<Warning>
  Error `-1009` means the account owes funds to the system (e.g., from unrealized losses exceeding the balance). You must deposit enough USDC to cover the arrears before any settlement can proceed.
</Warning>
