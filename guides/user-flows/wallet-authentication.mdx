LiqZero uses a two-layer authentication model to keep on-chain actions and API requests separately secured. Your user's wallet (via EIP-712) authorizes high-value operations like account creation, key registration, and withdrawals. A separate ed25519 keypair — the **LiqZero key** — signs every REST and WebSocket API call. This page explains both layers and walks you through generating and registering a LiqZero key.

## EIP-712 Wallet Signatures

LiqZero relies on the [EIP-712](https://eips.ethereum.org/EIPS/eip-712) standard to authenticate wallets for critical on-chain and protocol-level actions, including:

<CardGroup cols={3}>
  <Card title="Account Creation" icon="user-plus">
    Sign a `Registration` message to create a new account tied to your wallet and builder ID.
  </Card>
  <Card title="Key Registration" icon="key">
    Sign an `AddOrderlyKey` message to authorize a new LiqZero key for API access.
  </Card>
  <Card title="Withdrawals" icon="arrow-right-from-bracket">
    Sign a `Withdraw` message to authorize a withdrawal request from your account balance.
  </Card>
</CardGroup>

For all other interactions — placing orders, querying positions, managing account configuration — you sign requests using your LiqZero key rather than your wallet.

### EIP-712 Domains

LiqZero uses two EIP-712 domains depending on whether the action is processed entirely off-chain or verified on-chain.

<Tabs>
  <Tab title="Off-Chain Domain">
    The `Registration` and `AddOrderlyKey` types are verified off-chain. The `verifyingContract` is set to the canonical placeholder address.

    ```json
    {
      "name": "Orderly",
      "version": "1",
      "chainId": <your_chain_id>,
      "verifyingContract": "0xCcCCccccCCCCcCCCCCCcCcCccCcCCCcCcccccccC"
    }
    ```
  </Tab>
  <Tab title="On-Chain Domain">
    Types like `Withdraw` and `SettlePnl` are verified on-chain. Use the Ledger contract address for the LiqZero L2 chain — look it up in the [Smart Contract Addresses](/api-reference/contracts/addresses) reference.

    ```json
    {
      "name": "Orderly",
      "version": "1",
      "chainId": <your_chain_id>,
      "verifyingContract": "<ledger_contract_address>"
    }
    ```
  </Tab>
</Tabs>

## LiqZero Keys

A LiqZero key is an **ed25519 keypair** generated client-side and registered on-chain to your account. Once registered, you use the private key to sign every REST and WebSocket API request. LiqZero keys have two scope levels:

| Scope | Access |
|---|---|
| `read` | All private read-only endpoints (balances, positions, order history) |
| `trading` | All `read` endpoints plus order creation, modification, and cancellation |
| `asset` | Asset management operations (withdrawals, transfers) |

You can grant multiple scopes in a single key by passing them comma-separated (e.g., `read,trading`).

<Warning>
  LiqZero keys have a maximum expiry of **365 days** from the time they are added. Rotate keys before they expire to avoid authentication failures.
</Warning>

### Setting Up a LiqZero Key

<Steps>
  <Step title="Generate an ed25519 keypair">
    Use any standard ed25519 library to generate the keypair. The public key must be base58-encoded and prefixed with `ed25519:` when signing the EIP-712 message and when passing it to the API.

    <CodeGroup>
      ```java Java
      import net.i2p.crypto.eddsa.KeyPairGenerator;

      KeyPairGenerator keyGen = new KeyPairGenerator();
      KeyPair keyPair = keyGen.generateKeyPair();
      // Encode the public key as base58 and prefix with "ed25519:"
      String orderlyKey = Util.encodePublicKey((EdDSAPrivateKey) keyPair.getPrivate());
      ```

      ```python Python
      from cryptography.hazmat.primitives.asymmetric.ed25519 import Ed25519PrivateKey
      from base58 import b58encode

      def encode_key(key: bytes) -> str:
          return "ed25519:%s" % b58encode(key).decode("utf-8")

      orderly_key_obj = Ed25519PrivateKey.generate()
      orderly_key = encode_key(orderly_key_obj.public_key().public_bytes_raw())
      ```

      ```typescript TypeScript
      import { getPublicKeyAsync, utils } from "@noble/ed25519";
      import { encodeBase58 } from "ethers";

      const privateKey = utils.randomPrivateKey();
      const orderlyKey = `ed25519:${encodeBase58(await getPublicKeyAsync(privateKey))}`;
      ```
    </CodeGroup>
  </Step>

  <Step title="Sign the AddOrderlyKey message via EIP-712">
    Build the `AddOrderlyKey` message and sign it from the user's wallet. Use the **off-chain domain** (verifyingContract = `0xCcCCccccCCCCcCCCCCCcCcCccCcCCCcCcccccccC`).

    The message payload contains:

    | Name | Type | Required | Description |
    |---|---|---|---|
    | `brokerId` | string | Y | Your builder ID |
    | `chainId` | int | Y | Chain ID of the connected chain |
    | `orderlyKey` | string | Y | ed25519 public key (`ed25519:<base58>`) |
    | `scope` | string | Y | `read`, `trading`, `asset`, or comma-separated combination |
    | `timestamp` | timestamp | Y | Current time in UNIX milliseconds |
    | `expiration` | timestamp | Y | Key expiry in UNIX milliseconds (max 365 days ahead) |

    Example message:
    ```json
    {
      "brokerId": "your_broker_id",
      "chainId": 42161,
      "orderlyKey": "ed25519:HqN9uKJioHjAJZbadgQRGzq2e7huKg6foCyNY43hWbCk",
      "scope": "read,trading",
      "timestamp": 1685973094398,
      "expiration": 1717509094398
    }
    ```

## Using LiqZero Keys for API Authentication

Once the key is registered, sign every authenticated API request with the ed25519 private key and attach the following HTTP headers:

| Header | Value |
|---|---|
| `perpo-account-id` | The user's LiqZero account ID (bytes32 hex string) |
| `perpo-key` | The ed25519 public key — **without** the `ed25519:` prefix |
| `perpo-signature` | The base64url-encoded ed25519 signature of the request message |
| `perpo-timestamp` | Current UNIX timestamp in milliseconds |

<Warning>
  Pass the public key value **without** the `ed25519:` prefix in the `perpo-key` header. Only the raw base58 portion should be included. The prefix is required in the EIP-712 message during registration, but must be stripped for request headers.
</Warning>

<Tip>
  For full details on constructing the signature string and forming authenticated requests, see the [API Authentication](/api-reference/authentication) reference page.
</Tip>

## Key Expiry and Rotation

LiqZero keys expire at the timestamp you specify in the `expiration` field when registering (maximum 365 days from registration). To rotate a key:

1. Generate a new ed25519 keypair.
2. Sign a new `AddOrderlyKey` EIP-712 message from the user's wallet.
3. POST to `/v1/orderly_key` as described above.
4. Update your application to use the new private key for signing requests.

<Note>
  Multiple keys can be active simultaneously on a single account. You can register a replacement key before the old one expires to ensure zero downtime for your users.
</Note>

      public static String signatureToHashString(Sign.SignatureData signature) {
          byte[] retval = new byte[65];
          System.arraycopy(signature.getR(), 0, retval, 0, 32);
          System.arraycopy(signature.getS(), 0, retval, 32, 32);
          System.arraycopy(signature.getV(), 0, retval, 64, 1);
          return Numeric.toHexString(retval);
      }
  }
