LiqZero gives builders the trading infrastructure, liquidity access, and integration tooling needed to launch their own derivatives application without building the full stack from scratch. You can create a perpetual futures DEX on top of LiqZero's shared-liquidity orderbook while your users interact from any supported chain without switching to a separate trading chain in the product experience. This page covers what builders get from the integration, how LiqZero's three-layer architecture is organized, and the recommended path to start building.

## What Builders Get

Integrating LiqZero gives your application immediate access to a production-grade trading backend and the operational tooling to run it. Specifically, you get:

- **Shared liquidity** — access the same liquidity layer used across the LiqZero ecosystem from launch day, without bootstrapping an isolated orderbook
- **Orderbook infrastructure** — build on top of LiqZero's matching and order management services rather than operating your own engine
- **Omnichain user flows** — support account registration, deposits, withdrawals, and trading from all supported chains through a single integration
- **Flexible integration paths** — choose between React SDKs, UI components, Python tooling, or direct REST and WebSocket API access depending on your team's stack
- **Self-custody model** — users retain full control of their wallets and funds while interacting with your application

## High-Level Architecture

LiqZero's omnichain system is organized into three layers. Understanding these layers helps you know which part of the stack handles each user action and which APIs and contracts correspond to each concern.

<Steps>
  <Step title="Asset Layer">
    The Asset Layer lives on each supported chain and handles all user-facing on-chain actions. When a user connects their wallet to your application, registers an account, deposits USDC, or initiates a withdrawal, they are interacting with the Asset Layer. Each supported chain has its own deployed Vault contract that accepts deposits and processes withdrawal requests.

    **Relevant pages:** [Smart Contract Overview](/api-reference/contracts/overview) · [Smart Contract Addresses](/api-reference/contracts/addresses) · [Deposit & Withdrawal](/guides/user-flows/deposit-withdrawal)
  </Step>
  <Step title="Settlement Layer">
    The Settlement Layer lives on a single chain and acts as the transaction ledger behind the scenes. It records the authoritative state of all account balances, positions, and realized PnL across the system. You do not interact with this layer directly in most integration flows, but it is the source of truth that the Engine Layer and Asset Layer reference.

    **Relevant pages:** [Settle PnL](/guides/user-flows/settle-pnl) · [Smart Contract Overview](/api-reference/contracts/overview)
  </Step>
  <Step title="Engine Layer">
    The Engine Layer runs the orderbook and all related trading services used for order management and execution. When your user places a limit or market order, cancels an open order, or queries their open positions, they are communicating with the Engine Layer through LiqZero's REST and WebSocket APIs.

    **Relevant pages:** [API Introduction](/api-reference/introduction) · [API Authentication](/api-reference/authentication) · [Order Management](/guides/user-flows/order-management)
  </Step>
</Steps>

<Note>
  The three layers are independent but composable. A deposit flows from the Asset Layer (on-chain Vault contract) through the Settlement Layer (ledger credit) and makes funds available for trading in the Engine Layer — all without requiring your users to perform multiple explicit steps.
</Note>

## Integration Paths

Choose the path that best matches your team's technical stack and desired level of control over the UI and data layer.

<Tabs>
  <Tab title="Direct API">
    Build your own backend and frontend directly against LiqZero's REST and WebSocket interfaces. This path gives you the maximum flexibility to design your own data pipeline, UI, and business logic without any framework constraints.

    - REST base URL (Mainnet): `https://api.liqzero.com/`
    - REST base URL (Testnet): `https://testnet-api.liqzero.com`
    - Authentication: ed25519 signatures via `perpo-account-id`, `perpo-key`, `perpo-signature`, and `perpo-timestamp` headers

    Start with the [API Authentication guide](/api-reference/authentication) to understand how to construct signed requests before calling any private endpoints.
  </Tab>
  <Tab title="React SDKs">
    Use LiqZero's React-based SDKs to accelerate implementation on EVM chains. Three SDK layers are available:

    - **React Components SDK** — high-level drop-in UI components (trading panels, order forms, position tables) that can be themed to match your brand
    - **React Hooks SDK** — lower-level hooks for account, assets, orders, positions, funding, and market data that give you full UI control
    - **Core SDK** — foundational utilities for key management, signatures, and other primitives used by the hooks layer

    See the [SDK overview](/sdks/overview) for a comparison of all available packages and where to start.
  </Tab>
  <Tab title="Python Connector">
    Use the LiqZero Python connector for programmatic trading, algorithmic strategies, and backend integrations. The connector wraps LiqZero's REST and WebSocket APIs in an idiomatic Python interface and handles signature generation automatically.

    This is the recommended path for trading teams building execution bots, backtesting frameworks, or server-side order management systems.
  </Tab>
</Tabs>

## Start Here

Use the following pages as your structured builder onboarding path. Work through them in order to go from a blank project to a fully integrated trading application.

<Steps>
  <Step title="Plan the integration">
    Follow the [Integration Checklist](/introduction/getting-started/integration-checklist) for the complete build and launch sequence. This covers pre-integration setup, core implementation, advanced features, and go-live preparation.
  </Step>
  <Step title="Understand the system">
    Review the [Smart Contract Overview](/api-reference/contracts/overview) to understand how the on-chain contracts interact, then check the [Smart Contract Addresses](/api-reference/contracts/addresses) page for all deployed contract addresses across supported chains.
  </Step>
  <Step title="Implement core user flows">
    Work through each user flow in sequence:

    - [Accounts](/guides/user-flows/accounts) — create and activate user accounts on LiqZero
    - [Wallet Authentication](/guides/user-flows/wallet-authentication) — set up ed25519 keys for signed API access and trading actions
    - [Deposit & Withdrawal](/guides/user-flows/deposit-withdrawal) — support funding flows from any supported chain
    - [Order Management](/guides/user-flows/order-management) — place, cancel, and track orders
  </Step>
  <Step title="Cover trading operations">
    Extend your integration with the flows that make it operationally complete:

    - [Settle PnL](/guides/user-flows/settle-pnl) — handle realized PnL settlement as part of the account lifecycle
    - [Isolated Margin](/guides/user-flows/isolated-margin) — support per-position margin isolation
    - [Internal Transfer](/guides/user-flows/internal-transfer) — move funds between accounts without on-chain transactions
    - [WebSocket API](/api-reference/websocket/introduction) — stream real-time orderbook, trade, and execution report data
  </Step>
  <Step title="Integrate against the APIs">
    Use the [API Introduction](/api-reference/introduction) and [API Authentication](/api-reference/authentication) pages as your reference while implementing all REST endpoints. Review [Error Codes](/api-reference/error-codes) to build proper error handling into your application from the start.
  </Step>
  <Step title="Go live">
    Validate your integration on testnet, configure your builder fee structure, and coordinate your launch with the LiqZero team. Refer to the [Integration Checklist](/introduction/getting-started/integration-checklist) Phase 4 for the complete pre-launch verification steps.
  </Step>
</Steps>
