LiqZero is a headless trading infrastructure platform built on a three-layer omnichain architecture. Rather than requiring users to bridge assets to a single trading chain, the system separates concerns cleanly across an Asset Layer, a Settlement Layer, and an Engine Layer — letting users interact from any supported chain while sharing the same deep liquidity pool. As a builder, you own the frontend and user relationship; LiqZero owns everything behind it.

## The Three-Layer Architecture

Each layer has a single, well-defined responsibility. Together they make omnichain perpetuals possible without sacrificing self-custody or composability.

| Layer | Where It Lives | What It Does |
|---|---|---|
| **Asset Layer** | Every supported chain | Account registration, USDC deposits, and withdrawals. These are the user-facing smart contracts your dApp calls directly. |
| **Settlement Layer** | Single settlement chain | Acts as the authoritative transaction ledger. Records PnL settlements, tracks net balances, and coordinates cross-chain bookkeeping. |
| **Engine Layer** | Off-chain infrastructure | Runs the shared orderbook and matching engine. Handles order submission, cancellation, fill routing, and position management. |

### Asset Layer

The Asset Layer is deployed on every chain that LiqZero supports. When a user registers an account or moves funds, they interact directly with the Asset Layer smart contracts on whichever chain they are already using. This is the only layer your users ever touch on-chain. Builders integrate their frontend against these contracts to handle:

- **Account registration** — creating a LiqZero account linked to a wallet address
- **Deposits** — transferring USDC into the shared liquidity pool
- **Withdrawals** — requesting USDC back to the user's wallet on their chosen chain

### Settlement Layer

The Settlement Layer runs on a single designated chain and acts as the canonical record of truth for all balances and PnL. When a user's deposit arrives via the Asset Layer, a cross-chain message relays the accounting event to the Settlement Layer. When a trade is executed and PnL is realized, the Settlement Layer applies the balance change and makes it available for withdrawal back through the Asset Layer. Builders do not interact with the Settlement Layer directly — LiqZero infrastructure handles all relay logic.

### Engine Layer

The Engine Layer is LiqZero's off-chain order matching and execution service. It exposes the REST API and WebSocket API that your application integrates against. When a user places, modifies, or cancels an order, your backend or frontend calls the Engine Layer directly via authenticated API requests. The Engine Layer also broadcasts real-time market data — orderbook updates, trade feed, and execution reports — over WebSocket connections.

## How the Layers Interact

The three layers work in sequence for every user action:

<Steps>
  <Step title="User initiates action on Asset Layer">
    A user deposits USDC or registers an account by sending a transaction to the LiqZero smart contract on their chain (e.g., Arbitrum or Solana). This happens entirely within their existing wallet and does not require bridging.
  </Step>
  <Step title="Cross-chain message relays to Settlement Layer">
    The Asset Layer contract emits a cross-chain message that the LiqZero relay network delivers to the Settlement Layer. The Settlement Layer updates the user's account balance and marks it as ready for trading.
  </Step>
  <Step title="Engine Layer processes orders">
    Your application submits signed order requests to the Engine Layer REST API. The matching engine fills orders against the shared orderbook, updates positions, and reports execution results back via WebSocket. All fills are eventually settled back through the Settlement Layer.
  </Step>
  <Step title="User withdraws via Asset Layer">
    When a user requests a withdrawal, the Settlement Layer initiates a cross-chain message that releases funds on the user's target chain through the Asset Layer contract. The user receives USDC in their wallet without leaving your application.
  </Step>
</Steps>

## Why This Enables Omnichain

Traditional perp DEXes require users to bridge to a specific trading chain before they can deposit. LiqZero's Asset Layer removes this requirement by deploying user-facing contracts on every supported chain. From the matching engine's perspective, there is a single liquidity pool — regardless of which chain each deposit originated from. This means:

- **Unified liquidity:** Every builder's users contribute to and draw from the same orderbook depth.
- **No bridging UX:** Users stay on their home chain throughout registration, deposit, trading, and withdrawal.
- **Chain-agnostic position management:** A user who deposits on Base can withdraw to Arbitrum without any additional bridging step.

## Builder Role in the Architecture

LiqZero is a backend-only infrastructure layer. You — the builder — own the entire user-facing experience. This means you decide the branding, the feature set, the fee structure, and the supported chains you expose to your users. LiqZero provides the liquidity layer, the matching engine, the smart contracts, and the APIs. Your application calls those APIs and presents the results to your users.

## Smart Contract Flows

The smart contract layer handles four primary flows, all initiated at the Asset Layer:

<Accordion title="Deposit Flow">
  A user approves and calls the LiqZero vault contract on their chain. The contract locks USDC and emits a cross-chain message to the Settlement Layer, which credits the user's trading account. The deposit is reflected in the Engine Layer within seconds.
</Accordion>

<Accordion title="Trade Flow">
  Orders are submitted directly to the Engine Layer REST API using authenticated requests. The matching engine handles execution off-chain, records the fill, and updates the user's position and unrealized PnL in the Settlement Layer.
</Accordion>

<Accordion title="Settle PnL Flow">
  Users explicitly trigger PnL settlement when they want to realize gains or losses to their account balance. The Engine Layer initiates the settlement request, and the Settlement Layer applies the balance change and makes it withdrawable.
</Accordion>

<Accordion title="Withdrawal Flow">
  A user calls the withdrawal endpoint on the Engine Layer API. The Settlement Layer validates the balance, then emits a cross-chain message releasing USDC through the Asset Layer contract on the user's target chain.
</Accordion>

<Note>
  LiqZero's architecture is fully self-custodial. Users never hand custody of their assets to a builder or to LiqZero itself — funds are held in audited smart contracts and only released by the user's own signed transactions. Your application facilitates the interaction; it does not hold user funds.
</Note>
