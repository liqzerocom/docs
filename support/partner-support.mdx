LiqZero provides dedicated support for builders at every stage — from initial architecture review and SDK setup through launch preparation, post-launch monitoring, and scaling. This page maps out the support channels, builder resources, and partnership programs available to you as a LiqZero integration partner. Use it as your reference for where to go when you need help, co-marketing support, or access to builder programs.

## During Onboarding

Before you write any code, align your integration plan with the LiqZero team. This avoids common integration pitfalls and ensures your architecture matches what the platform supports.

<Steps>
  <Step title="Complete builder setup">
    Register your builder identity by completing the [broker onboarding guide](/introduction/getting-started/what-is-liqzero). This creates your unique `brokerId`, which is required for all API requests, SDK provider configuration, and on-chain contract interactions. If you are using the LiqZero One portal, complete the graduation flow at [dex.orderly.network](https://dex.orderly.network/dex) to create and confirm your builder ID.
  </Step>
  <Step title="Review architecture and scope">
    Work with the LiqZero team to review your integration plan — the chains you'll support, the user flows you'll implement (deposits, withdrawals, order types, margin modes), and any custom requirements. Aligning on scope before development begins prevents costly rework later.
  </Step>
  <Step title="Align on launch milestones">
    Use onboarding discussions to define launch readiness criteria, implementation milestones, and any rollout dependencies (e.g., chain support, liquidity provisioning, marketing announcements). The LiqZero team can advise on sequencing and flag any open prerequisites.
  </Step>
</Steps>

## After Launch

Your responsibilities don't end at launch. Production DEXes need ongoing monitoring and a clear process for handling maintenance windows and user issues.

<Accordion title="Monitor system maintenance windows">
  Poll the [system maintenance status endpoint](/api-reference/introduction) at regular intervals and surface maintenance windows clearly in your DEX UI. During maintenance, trading and data feeds may be unavailable — communicate this to your users proactively rather than letting them see blank data or connection errors.
</Accordion>

<Accordion title="Handle user support escalations">
  Establish a clear internal process for user-reported issues. Use the [LiqZero Dashboard](https://orderly-dashboard.orderly.network/) to retrieve account state and history for any affected user. If the issue stems from platform behavior rather than your integration, escalate to the LiqZero Discord support channel with full context (wallet address, chain, timestamp, transaction hash or order ID).
</Accordion>

<Accordion title="Stay current with SDK and API updates">
  Watch the [SDK Release Notes](/sdks/overview) and monitor the builder Telegram channel for API deprecation notices, contract upgrades, and SDK version announcements. Breaking changes are communicated in advance — update your integration before the deprecation deadline.
</Accordion>

<Accordion title="Operational readiness checklist">
  Before going live, confirm that your DEX handles the following scenarios:
  - Maintenance mode display when the system status endpoint signals downtime
  - Graceful degradation when WebSocket connections drop (automatic reconnection)
  - Clear user messaging for order rejections with actionable guidance
  - Withdrawal delay explanations for cross-chain transactions
  - Gas estimation and approval flow for deposits on each supported chain
</Accordion>
