Withdrawals on LiqZero are cross-chain operations processed through LayerZero messaging. When a user requests a withdrawal, LiqZero initiates a cross-chain message from the LiqZero settlement layer to the destination chain, where the user's USDC is released from the Vault contract. This means withdrawals are not instant — processing time varies by destination chain and network conditions. Before treating a withdrawal as stuck, verify that the expected processing time has elapsed for the target chain.

<Note>
  Some chains require significantly longer withdrawal times than others. Chains like Polygon require more block confirmations before finality, which extends the relay window. In normal conditions, most withdrawals complete within **2–10 minutes**, but can take longer during network congestion.
</Note>

## Expected Withdrawal Timing

| Chain | Typical Processing Time |
|---|---|
| Arbitrum | 2–5 minutes |
| Optimism | 2–5 minutes |
| Base | 2–5 minutes |
| Ethereum | 5–15 minutes |
| BNB Smart Chain | 3–8 minutes |
| Avalanche | 3–8 minutes |
| Mantle | 5–15 minutes |
| Sonic | 3–8 minutes |
| SEI | 3–8 minutes |

If the withdrawal has not arrived after the expected window, proceed with the diagnostic steps below.

## Diagnostic Steps

<Steps>
  <Step title="Confirm the withdrawal request was accepted">
    Query the user's asset history to confirm that LiqZero received and processed the withdrawal request. A withdrawal that appears in the history with a `processing` or `completed` status was accepted by the system. See the [Asset History endpoint](/api-reference/rest/assets) for full response schema and filter options.

    ```bash
    GET https://api.liqzero.com/v1/asset/history?type=WITHDRAW
    ```

    Required headers: `perpo-account-id`, `perpo-key`, `perpo-signature`, `perpo-timestamp`

    ```json
    {
      "success": true,
      "data": {
        "rows": [
          {
            "id": "12345678",
            "tx_id": "0xabc123...",
            "amount": "500.00",
            "token": "USDC",
            "chain_id": 42161,
            "status": "COMPLETED",
            "created_time": 1716000000000,
            "updated_time": 1716000300000
          }
        ]
      }
    }
    ```

    <Warning>
      If the withdrawal does **not** appear in the history, the user's request was never received by the system. Ask the user to re-submit the withdrawal — ensure their wallet signed the withdrawal request correctly and that the request reached the API without a timeout.
    </Warning>

    Also verify the `chain_id` in the response matches the chain the user expected. Users occasionally submit a withdrawal to the wrong chain — the funds will arrive on the unintended chain rather than their intended destination.
  </Step>

  <Step title="Check the LayerZero message status">
    Navigate to [LayerZero Scan](https://layerzeroscan.com/) and filter by **Source: Orderly** to see all cross-chain messages initiated from the LiqZero settlement layer.

    Locate the message corresponding to the user's withdrawal by matching the approximate timestamp. Look for one of these statuses:

    | Status | Meaning |
    |---|---|
    | **Delivered** | The message arrived at the destination chain successfully. Check the destination chain (Step 3). |
    | **Inflight** | The message is still being relayed. If inflight for more than 10 minutes, LayerZero may be experiencing relay delays. |
    | **Failed** | The message delivery failed. This may indicate a cross-chain fee issue — see the note below. |

    <Note>
      **Cross-chain fee scenario:** If the destination chain Vault has insufficient liquidity to fulfill the withdrawal, an additional cross-chain fee is deducted from the withdrawal amount and the transaction is retried. The user will receive slightly less than the requested amount. This is expected behavior and not a bug.
    </Note>
  </Step>

  <Step title="Check the destination chain block explorer">
    Once the LayerZero message shows **Delivered**, the funds should be visible in the user's wallet. If they're not, check the destination chain's block explorer using the transaction hash from the LayerZero Scan message details.

    - Confirm the transaction is **confirmed** (not pending).
    - Verify the destination address matches the user's wallet address.
    - Check the token transfer log to confirm USDC was credited to the correct address.

    If the transaction is confirmed on-chain but the user does not see the funds in their wallet, the issue is wallet-side (e.g., the wallet may not be displaying the USDC token on that specific chain). Ask the user to add the USDC token contract for that chain to their wallet.
  </Step>

  <Step title="Check the Dune support dashboard">
    The [LiqZero Dune Dashboard](https://dune.com/orderly_network/orderly-support-dashboard) provides an aggregated view of withdrawal activity across all chains. Search by wallet address to see all processed withdrawals and confirm which chain the funds were sent to.

    Refresh the dashboard before checking — it may display cached data by default.
  </Step>

  <Step title="Escalate via Discord if still unresolved">
    If the withdrawal is not found in the asset history, does not appear in LayerZero Scan, or has been in-flight for more than 30 minutes, submit a support ticket in the [LiqZero Discord](https://discord.gg/OrderlyNetwork).

    Include the following information in your ticket:

    - User's wallet address
    - Withdrawal amount and token
    - Destination chain
    - Approximate time the withdrawal was requested (UTC)
    - Transaction hash or withdrawal ID from `GET /v1/asset/history` (if available)
    - Screenshot or link from LayerZero Scan showing the message status
  </Step>
</Steps>

## Frequently Asked Questions

<Accordion title="Why did the user receive less than the requested withdrawal amount?">
  If the destination chain Vault had insufficient liquidity at the time of the withdrawal, a cross-chain bridging fee was deducted and the transaction was re-routed through an alternative path. The difference between the requested amount and the received amount represents this fee. This is expected behavior — it is not a system error or funds loss.
</Accordion>

<Accordion title="The user withdrew to the wrong chain. Can the funds be recovered?">
  If the funds were delivered to the correct wallet address on the wrong chain, the user can bridge the USDC back to their intended chain using a third-party bridge. LiqZero cannot reverse a completed on-chain withdrawal. To avoid this in the future, double-check the `chain_id` in the withdrawal request before signing.
</Accordion>

<Accordion title="The LayerZero message shows Inflight for more than 30 minutes. What should I do?">
  Extended inflight times beyond 30 minutes indicate a LayerZero relay delay on the destination chain. These delays are rare and typically resolve themselves within a few hours. If the message has been inflight for more than 2 hours, escalate to support via Discord with the LayerZero message details.
</Accordion>

<Accordion title="The withdrawal shows COMPLETED in asset history but the user hasn't received funds.">
  A `COMPLETED` status means the cross-chain message was sent from the LiqZero settlement layer. Check the destination chain block explorer to confirm the receiving transaction was included in a block. If it was, ask the user to add the USDC token contract for the destination chain to their wallet so the balance displays correctly.
</Accordion>
